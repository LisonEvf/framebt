# 能力验证预登记（写于运行回测之前）

> **本文件在跑任何回测之前写定**，用于固定「要检验什么、预期是多少、什么算失败」。
> 运行时间：见文件末尾 git 状态与生成报告时间戳。生成物：`reports/CAPABILITY.md`。
> 执行脚本：`tools/validate_capability.py`。

---

## 0. 这次要验证的到底是什么

框架的**能力**不是「能跑出数字」，而是四条可被证伪的性质：

| # | 待验证性质 | 为什么它是「能力」 |
|---|---|---|
| A | **账本/成本/成交的语义可精确预测** | 若无法用另一套独立代码复算出同样的现金与权益，框架的任何一个业绩数字都不可信 |
| B | **因果纪律真的挡住了前视** | 前视不是靠「作者小心」，而要靠机制；机制必须能被攻击并被挡住 |
| C | **信号 → 盈亏的传导不歪曲** | 排序方向一翻，盈亏必须跟着翻；否则引擎在暗中改写策略意图 |
| D | **摩擦与制度约束的代价可解释** | 扣掉的钱要能被逐项对账（佣金/印花/滑点/整手/涨跌停/T+1），不能是黑箱 |

「策略赚钱」**不是**本次的验证目标。策略只用来看 B/C/D 是否成立；它的经济结论单独、诚实地报告。

## 1. 被测策略（具体、可复现、非玩具）

**LowVol-10：流动性池内的低波动组合（月度调仓）**

| 项 | 设定 | 说明 |
|---|---|---|
| 池 | 全 A **2013-01-01~2015-12-31 日均成交额前 300**，且该窗口内 ≥400 个交易日 | 池在评估期之前**一次性固定**，不按业绩筛选、不逐日重排 |
| 评估期 | 2016-01-01 → 数据末（2026-10-15） | 喂入数据自 2015-10-01 起，策略自然预热 |
| 信号 | 过去 60 个交易日**已实现波动率**（日收益标准差，年化）**最低的 10 只** | 低波动异象（leverage-constraint / lottery-preference） |
| 权重 | 等权，gross = 98% 权益，**100 股整手向下取整** | 20 万本金，单只 ≈ 1.96 万 |
| 调仓 | 每 21 个交易日一次；非调仓帧不下单（不漂移） | 换手可预期 |
| 可行性过滤 | trailing 20 日均成交额 ≥ 2000 万；`close×100 ≤ 8%` 权益（一手买不起就不进） | 都是 **PIT**（只用 t 及以前） |
| 成交 | 帧 t 收盘决策 → **帧 t+1 开盘价成交**（引擎 I2 延迟管线） | 因果最保守口径 |
| 成本 | 佣金 3bp（最低 5 元/笔）· 印花税 5bp（仅卖）· 过户费 0.2bp · 滑点 5bp（比例） | |
| 制度 | T+1、±10% 涨跌停、100 股整手 | |
| 对照臂 | **HighVol-10**：同一份代码只把排序方向反过来（取波动率最高的 10 只） | 信号传导的对照实验 |

**为什么这个策略值得做（价值）**：低波动异象是 A 股里少数有明确经济机制（杠杆约束 / 彩票偏好）且换手天然低的横截面效应；它正好考验「整手取整 + T+1 + 涨跌停 + 印花税」这些把纸面 alpha 吃掉的真实摩擦，而本项目此前只测过动量/反转/8 因子，**从未测过低波动**。

**偏误声明（先写）**：数据源不含退市股，故池本身是「2013–2015 还算活跃、至今仍存续」的标的，**存活偏差存在且无法消除**；本报告的绝对收益不得外推为可交易业绩。

## 2. 独立预期值从哪来（不依赖 framebt）

全部预期值由**与引擎无共享代码**的三套参考计算给出：

| 代号 | 参考实现 | 用途 |
|---|---|---|
| **R1 克隆** | 纯 numpy/pandas 逐日循环，独立复现「决策→次日开盘成交→整手→T+1→涨跌停→成本」全过程 | 与引擎**逐笔对账**（成交明细 + 权益曲线） |
| **R2 分数权重** | 同信号、无整手、无成本、次日开盘成交的向量化组合 | 给出「理想摩擦为零」的收益上界 |
| **R3 同日收盘成交** | 同信号、无成本，但**用发出信号那根的收盘价成交**（经典向量化回测口径，含前视） | 量化「能被前视偷走多少收益」 |
| **R4 五分位统计** | 纯 pandas：按 60 日波动率分 5 组，统计各组未来 21 日收益 | 给出横截面效应的**独立**预期方向与量级 |

## 3. 预登记预测（逐条给出判据；跑完不许改）

| 编号 | 预测 | 判据（成功条件） | 失败的含义 |
|---|---|---|---|
| **P1** | 账本可外部审计：用 `FillEvent` 明细独立重算的现金/权益 == 引擎逐帧权益 | 最大相对偏差 **< 1e-9** | 账本口径有未知项，任何业绩数字作废 |
| **P2** | 成本可精确核验：每笔 `fill.cost` == 手算 `max(n×3bp,5) + 卖 5bp + 0.2bp + n×5bp` | 最大绝对偏差 **< 1e-9 元** | 成本模型与文档不符 |
| **P3** | 确定性（I3）：同配置两次运行 | 权益曲线与成交明细**逐位相同** | 回测不可复现 |
| **P4** | 无成本克隆等价：关闭成本后的引擎 == R1 克隆 | 最终权益相对差 **< 1e-9**；成交 (symbol, ts, side, size) **100% 一致** | 引擎的成交/整手/延迟语义与独立实现不一致 |
| **P5** | 摩擦代价可预测：`年化(引擎含成本) = 年化(R1含成本参照) − 费用拖累`，其中费用拖累 = 年化单边换手 T × 单边平均费率 0.127% | 预测 **T ∈ [2, 6]×**；预测拖累 **0.25%~0.80%/年**；实测落在预测 ±0.35pp 内 | 成本或换手不可解释 |
| **P6** | 风险结构：低波动组合的已实现年化波动 / 池等权波动 ∈ **[0.55, 0.90]**，且最大回撤**小于**池等权 | 两条同时成立 | 波动率信号没被正确执行 |
| **P7** | 信号传导：`年化(LowVol) − 年化(HighVol)` 与 R4 的 `D1 − D5` 预期**同号**，绝对差 ≤ 8pp/年 | 同号且 ≤ 8pp | 引擎歪曲了信号排序 |
| **P8** | 因果防御：伪造 token（issued_at 提前）+ 负 lag 请求 | 逃逸次数 **= 0**；负 lag 抛 `CausalityViolation` | 前视可被利用 |
| **P9** | 前视溢价可量化：`年化(R3 同日收盘) − 年化(R2 次日开盘)` | 只测量、给数（**不预设符号**），要求 \|溢价\| ≤ 10pp/年以确认不是引擎伪造出来的 | 溢价离谱说明成交口径异常 |

> P1–P4 是**精确判据**（可证伪到机器精度）；P5–P7 是**定量/方向判据**（给出区间）；P8 是**对抗判据**；P9 是**测量项**。

---

## 4. 允许的诚实结论

- 若 P1–P4 全过：引擎的账本与成交语义在真实数据上可被独立复算 —— 这是「回测不骗你」的**工程证据**。
- 若 P5–P7 有不过：如实写明引擎在处理整手/T+1/涨跌停/成本时与预期的偏差来源，**不调参掩盖**。
- 策略本身的盈亏（含存活偏差、单一历史区间、20 万约束）**不构成有效性证明**，无论正负。

## 附录 A · 事后修订记录（跑之后才加，逐条说明为什么）

预登记要求「跑完不许改」。以下是两次**必须**修的修订，都写清楚原因、时间与影响范围。
修订的判据是：**只改「我怎么算」，不改「什么算成功」**。

### A1（数据体检 + 评估区间 2016→2018）

**触发**：第一次全量跑（不清洗，2016-01 起）的结果是 LowVol 年化 −0.94%、
**HighVol 年化 +37.25%**、个别标的单日 **+1650%**、池等权基准出现 `inf`。
追查原始 parquet 后确认是数仓 `QFQ` 口径缺陷（`SH.601088` 起始 close = −4.70、
`SZ.000338` 起始 close = 0.02、`SH.601919` 有 2309 根 ≤0 的 Bar），
越过零点后跳回正价 → 制造 +1650% / +900% / inf% 的假日涨跌幅。
框架自带数据源只过滤「≤0 的价格」，拦不住这类跳变。

**修订**：
1. 加入逐标的体检：丢弃非法 Bar；若出现超板块涨跌停上限的跳变（主板 11%、创业板/科创板 21%），
   截断到最后一次断裂之后；截断后不足 400 根剔除。
2. 评估区间由 **2016-01** 改为 **2018-01**（喂入数据自 2017-01 起）。
   理由：2016–2017 的可用截面只有 108/291，且复权断裂最集中；2018 起截面 123 → 290。

**影响**：预测 P1–P9 的**判据未改**；只有被检验的样本期变短（8.45 年）。
未清洗的 2016–2026 首跑结果原样保留在 `reports/CAPABILITY.md` §12 作为反面教材。

### A2（P5 拆成 P5a / P5b）

**触发**：预登记里写「费用拖累 = 年化单边换手 T × 单边平均费率」，但
①「单边换手」在代码里曾按 `traded/equity/years/2`（回合制）定义，与公式不自洽；
② 费率取 0.127% 是估读，按费率表精算是 0.107%。
两个口径混在一起会让「预测 vs 实测」失去意义。

**修订**：拆成
- **P5a**（恒等式）：`费用拖累 = 年化单边换手（traded/equity/years）× 0.107% ± 0.35pp`
- **P5b**（量级）：`年化单边换手 ∈ [2, 6]×`

**影响**：P5b **未通过**（实测 9.66×）。这是真实的预期错误，如实记录，不调参掩盖。
