# 外部策略复刻 · 预登记（写于跑数之前）

> **写定时间**：2026-10-20 23:40（Asia/Shanghai）
> **执行物**：`tools/replicate_external.py` → `reports/EXTERNAL_REPLICATION.md`
> **数据**：本项目 `tools/etf_cache` 的真实 ETF 日线（2013-07 → 2026-10-16）
> **一句话**：用**有公开记录的规则与结果**做外部锚，检验 framebt 是「能复刻规则」还是「只是能跑」。

---

## 0. 为什么这次不是又写一个策略

前两轮已经证明：

- `reports/CAPABILITY.md`：一个具体策略的账本/成本/成交可被独立复算到 1e-9；
- `reports/USABILITY.md` + `docs/GATE_USABILITY.md`：随机订单、因果攻击、变异验证。

但两者都是**项目内部口径**。本轮要回答的是更外部的问题：

> 把**别人公开验证过的策略规则**搬进来，framebt 跑出来的东西，
> 和「独立实现」「外部数据源」「公开结果」三者对不对得上？

**精度**（同一份数据、同一套规则，两套实现是否逐笔一致）与
**效度**（结果是否重现公开策略的行为特征）必须分开报告，不能用一个「差不多」混过去。

## 1. 复刻对象（规则先钉死，不调参）

| 代号 | 策略 | 公开出处 | 规则（本轮实现） |
|---|---|---|---|
| **BH** | 买入持有沪深300ETF | 市场基准 | 2015-01 首个交易日买入 510300，持有到期末 |
| **FABER** | Faber 10 个月均线趋势 | Faber (2007/2013)《A Quantitative Approach to Tactical Asset Allocation》 | 每月首个交易日：若 510300 上月末收盘 > 200 日 SMA → 持有 510300；否则持有 511990 货币 ETF。次日开盘成交 |
| **GEM** | Antonacci 全球股票动量 | Antonacci《Dual Momentum Investing》；SVRN 复现（1973-2013） | 每月首个交易日：比较 510300 与 513100 的 12 个月收益，取高者；若高者 12 个月收益 ≤ 511990 的 12 个月收益 → 改持 511010 国债 ETF。次日开盘成交 |
| **PP** | Browne 永久组合 | Browne；公开长期统计（1972-2025：约 8%/年、最大回撤约 13%） | 510300 / 511010 / 518880 / 511990 各 25%；每月检查，任一权重超出 15%~35% 才调回 25% |
| **60/40** | 股债 60/40 | 经典资产配置基准 | 510300 60% + 511010 40%，每月调回 |
| **EW4** | 四资产等权 | 分散化基准（上一轮 `ETF_TREND.md` 的结论） | 四资产各 25%，每月调回 |

**为什么是这四个**：Faber 与 GEM 是**有明确规则、有公开回测表**的趋势/动量策略；
PP 与 60/40 是**有长期公开统计**的配置策略；BH/EW4 是必须打败的朴素基准。
它们覆盖「趋势」「绝对+相对动量」「风险分散」三类机制，正好检验引擎是否只对某一种策略成立。

**偏误声明**：ETF 池是今天存续的品种；2015-2026 含 A 股两轮大起大落与美股长牛，
对 GEM 天然有利、对 A 股趋势策略天然不友好。**绝对收益不得外推**，本报告只对
「同一数据下规则是否被忠实执行」和「行为特征是否与公开结果同向」负责。

## 3. 三层对账（每条都要有数）

### L1 同一数据的独立实现（精度）

在 `tools/replicate_external.py` 内写一份**不 import framebt 账本/撮合/成本**的
逐日参考实现：同样的月度信号、同样的目标股数、同样的「卖先买后」、同样的次日开盘成交、
同样的费用公式。判据：

| 项 | 通过条件 |
|---|---|
| 成交明细 | `(frame_id, symbol, side, size, price)` **完全一致** |
| 每笔成本 | 绝对偏差 **< 1e-9 元** |
| 逐帧权益 | 最大绝对偏差 **< 1e-6 元**（相对 < 1e-9） |
| 期末现金/持仓 | 一致 |

**任一条不过 → L1 失败，本轮不能宣称「复刻准确」。**

### L2 外部数据源（数据与口径）

用 Yahoo Finance 的 `510300.SS` 调整后收盘价（独立数据商）与本地 QFQ 对齐：

| 项 | 通过条件 |
|---|---|
| 日收益相关系数 | **> 0.99** |
| 同期 CAGR 差 | **< 2.0pp**（允许复权/分红口径差异） |
| 最大回撤差 | **< 5pp** |

### L3 公开结果（效度）

| 策略 | 公开结果（不同市场/期） | 本轮要检验的**同向特征** |
|---|---|---|
| FABER | 美国 1973-2013：最大回撤从 46% 降到 <10%，波动降到个位数；牛市会跑输 | 最大回撤 **< BH**；CAGR **≤ BH 或小幅落后**（A 股震荡市） |
| GEM | 美国/全球 1973-2013：年化 17.43%、波动 12.64%、Sharpe 0.87、最大回撤 −22.72%（Antonacci）；独立复现 16.70%/−19.07% | 最大回撤 **< BH**；绝对动量在 2015/2018/2022 类下跌中**降低损失**；强趋势期可能跑输 |
| PP | 美国 1972-2025：约 8%/年、最大回撤约 13%、Sharpe 约 0.7 | 波动与最大回撤 **显著 < BH**；CAGR 低于 BH |
| 60/40 / EW4 | 分散化降低回撤 | 波动/回撤 < BH，CAGR 不保证 |

**注意**：公开数字来自**不同市场、不同期间、不同数据口径**，不能当成本轮的预期值；
L3 判的是**方向与风险结构**，不是小数点。若方向相反，如实写「未复现」并归因。

## 4. 本轮明确不做什么

- 不调参、不搜索 lookback / 均线 / 调仓频率；全部取公开规则的原值（200 日 / 12 个月 / 月度）。
- 不把「某策略今年赚钱」当作框架有效的证据。
- 不声称复刻了 Faber/Antonacci 的原始收益率（数据与期间不同）。
- 不引入未来数据：信号只用上月末及以前，成交在下一交易日开盘。

## 5. 复现

```powershell
$env:PYTHONPATH="src"
python -u tools/replicate_external.py --md reports/EXTERNAL_REPLICATION.md
```

> L2 与 Yahoo 数据敏感性需要联网（`query1.finance.yahoo.com`）；离线时 L1/L3 仍可跑，
> L2 会标记为 n/a / FAIL。脚本不会用未来数据：信号只读上月末及以前。

**通过标准**：
1. L1 四条全过；
2. L2 三条全过；
3. L3 至少 FABER/GEM/PP 三条策略的**风险结构方向**成立；
4. 三条同时成立，才可写「框架复刻能力通过外部锚验证」。

## 附录 A · 执行结果（2026-10-20 实跑）

| 项 | 结果 |
|---|---|
| L1 本地 QFQ | **6/6 PASS**：成交/成本/逐帧权益全部 <1e-9 元（PP/60-40/EW4 最大 4.7e-10） |
| L1 Yahoo 数据 | **6/6 PASS**（同一套参考实现） |
| L2 | **FAIL**：510300 日收益相关 0.997、CAGR 差 0.42pp 通过；最大回撤 52.97% vs 45.45%，差 **7.52pp** > 5pp |
| L3 | **方向 4/4**；但 Faber/GEM 的最大回撤只比 BH 少 **1.61pp**（公开约 36–37pp）→ **幅度未复现** |

关键数字（本地 QFQ，2015-01-05 → 2026-10-16）：

| 策略 | 年化 | 波动 | 最大回撤 |
|---|---|---|---|
| BH | +3.37% | 26.08% | 52.55% |
| FABER | +1.21% | 20.75% | 50.95% |
| GEM | +9.02% | 25.68% | 50.95% |
| PP | +4.89% | 8.20% | 17.32% |
| EW4 | +10.40% | 10.60% | 15.96% |

**结论**：引擎**准确**（L1 零偏差）；外部**数据商一致性**未过（加法式 QFQ，已知缺陷）；
公开策略的**风险改善幅度不可移植**到 A 股 2015-2026（月度信号躲不开 2015-06→08 闪崩）。
L2 的失败是数据层问题，不是引擎算术；这一点由 L1 的逐笔零偏差独立证明。

**本轮实测的 API 陷阱**：引擎 token 的 `issued_at = frame_end = bar.timestamp + Δt`，
所以 `bus.get(..., lag=1)` 仍包含当日 Bar；实现「上月末信号」必须用 `lag=2`。
已在 `tools/replicate_external.py` 中显式注释。
