# 自适应多因子系统 · 落地实现说明

> 对应设计文档《即时事件驱动 + 持续自适应的多因子系统：完整落地实践文档》。
> 本文诚实标注**哪些已实现、哪些因数据/依赖缺失无法实现、以及为什么**。

## 0. 一句话总览

在 `framebt` 引擎之上，落地了设计文档中**可由日频价量数据实现**的部分：

| 设计文档 | 状态 |
|---|---|
| §1 三条公理 / 三层解耦 | ✅（由 framebt 引擎承载） |
| §2 因子体系层（因子库 + 预处理 + 筛选） | ✅ 57 因子 + 完整流水线 |
| §3 权重优化层（复合损失 + 在线 GD + 门控） | ✅ |
| §4 执行与验证层（PIT + 事件驱动回测） | 🟡 回测/PIT 由 framebt 保证；**实盘并行验证无实盘可验证** |
| §5 监控层（IC/ICIR/FSC/拥挤度 + CUSUM + 三级预警） | ✅ |
| §6 自主因子发现（符号回归 / 神经网络 / 入栈流水线） | ✅ |
| §7 生命周期管理 | ✅ |
| 阶段一 DolphinDB 流批一体 | ❌ **无 DolphinDB、无 L2 流数据** |
| 事件驱动因子（新闻/GMM 事件识别） | ❌ **无资讯事件数据** |

**结果（严格样本外）**：24 只 A 股 × 2000 根日线，样本内 800 日选因子 → 样本外 1251 日回测，
**+42.47% vs 等权买入持有 +16.71%（超额 +25.76%）**，Sharpe 0.37，最大回撤 31.53%，
已扣除 A 股成本（佣金/印花税/过户费/滑点）共 12.3% 初始资金。

## 1. 核心原则的落地：三者共享同一套逻辑

> 设计文档：「因子定义、权重计算、回测执行三者共享同一套逻辑，不因运行模式而分叉。」

这是本实现的**首要架构约束**，具体做法：

```
                    ┌──────────────────────────────┐
                    │  factors/library.py          │
                    │  每个因子 = (Panel) -> Frame │  ← 唯一定义
                    └──────────────┬───────────────┘
                                   │
              ┌────────────────────┴────────────────────┐
              ▼                                         ▼
   ┌──────────────────────┐                 ┌──────────────────────┐
   │ 研究/评估（整段面板） │                 │ 回测（逐帧因果切片） │
   │ Panel.from_feed()    │                 │ Panel.from_bus(token)│
   │ screen_pool / IC     │                 │ AdaptiveStrategy     │
   └──────────────────────┘                 └──────────────────────┘
```

`Panel` 是一组对齐的 DataFrame（index=时间戳, columns=标的）。因子函数**只认 Panel**，
因此不存在第二份因子实现。研究路径把整段历史喂进去；回测路径每帧从**因果总线**取窗口。

**可证明无前视**：`Panel.from_bus()` 受 `CausalToken` 约束（且总线钳制伪造令牌），
而验证脚本的**因果审计**会抽样检查「预计算面板的第 t 行」是否等于「只用 ≤t 数据重算的第 t 行」
—— 实测逐位一致（`tools/validate_adaptive.py` 第 3 节）。

> DolphinDB 的「流批一体」是用同一份因子代码同时驱动批计算与流计算；
> 本实现用同构的方式达成同一目的：**同一份因子代码同时驱动研究(批)与回测(逐帧)**。
> 差别在于本实现没有实时行情流可接入（见 §5 边界）。

## 2. 模块结构

```
src/framebt/
├── factors/                    # §2 因子体系层
│   ├── ops.py                  #   WQ101 算子集（截面/时序/逐元素 + 安全除法 + 逐行相关）
│   ├── panel.py                #   Panel：研究/回测共用的数据形状
│   ├── library.py              #   57 个因子（WQ101 子集 + GTJA191 代表）
│   ├── preprocess.py           #   MAD 去极值 → 标准化 → 中性化 → 相关性去冗余
│   ├── evaluate.py             #   IC / ICIR / Newey-West t / 分组单调性 / 筛选
│   └── lifecycle.py            # §7 因子生命周期状态机
├── portfolio/                  # §3 权重优化层
│   ├── weights.py              #   复合损失 + 在线梯度下降（Adam + 折扣 + 近端 L1）
│   ├── gating.py               #   市场状态门控网络（numpy 手写 BP，确定性）
│   └── combine.py              #   因子合成 → 目标权重（含缓冲带）→ 目标股数
├── monitor/                    # §5 监控层
│   ├── changepoint.py          #   双侧 CUSUM + 卡尔曼滤波 + 衰退概率 + 参数敏感性
│   └── health.py               #   IC/ICIR/FSC/拥挤度看板 + 三级预警 + 自动降权
├── discovery/                  # §6 自主因子发现
│   ├── symbolic.py             #   符号回归（遗传规划，自实现，无 gplearn/deap）
│   ├── neural.py               #   神经网络隐因子（PyTorch，可选）
│   └── pipeline.py             #   正交化 / VIF / 增量 ICIR / 影子运行 / 入栈
└── strategies/
    └── adaptive_multi_factor.py # 因果在线学习策略（把上面全部串进 framebt 引擎）
```

配套：
- `tools/validate_adaptive.py` —— 严格样本内/外验证 + 因果审计 + 基准对比
- `reports/ADAPTIVE.md` —— 验证报告（生成物）
- `tests/test_factors.py`、`test_portfolio.py`、`test_adaptive_system.py`、`test_discovery_pipeline.py`

## 3. 设计文档章节 → 实现对照

### §2 因子体系层

| 设计要求 | 实现 | 说明 |
|---|---|---|
| WQ101 / GTJA191 因子库 | ✅ 57 个 | 仅收录**可由日频 OHLCV + vwap + 市值推导**的因子。原版依赖行业分类 `indclass` 的约 19 个 WQ 因子、以及依赖财务数据的因子**未收录**（本数据集无行业与财务 PIT 数据） |
| MAD 去极值 | ✅ | `median ± 3 × 1.4826 × MAD`，逐截面 |
| 标准化 | ✅ | 截面 z-score |
| 中性化 | 🟡 | 对 **log 市值**做截面回归取残差；**行业哑变量缺失**（无行业分类数据） |
| 相关性去冗余 | ✅ | 两两截面 Spearman > 0.7 的簇保留 \|ICIR\| 最大者 |
| 因子池筛选（IC/t/相关性/单调性/样本量） | ✅ | 阈值见 `evaluate.DEFAULT_SCREEN`，与附录 A 一致 |
| 事件识别层（GMM 四分类） | ❌ | **无资讯事件数据**，无从训练 |
| 事件驱动因子即时生成 | ❌ | 同上 |

**因子库实测**（样本内 800 日，24 标的）：10/57 通过 IC/t/单调性 门槛，去冗余后保留 **8 个**。

### §3 权重优化层

| 设计要求 | 实现 | 说明 |
|---|---|---|
| 复合损失 `−ICIR + λ₁·Turnover + λ₂·‖w‖₁` | ✅ | ICIR 由折扣 IC 均值/方差在线估计 |
| 在线梯度下降 + 折扣率 β | ✅ | Adam + 缓冲区按 `β^age` 加权累加梯度，β=0.95 |
| 「先预测、后观察标签、再更新」 | ✅ | 每帧用 `factor[t−1]` 与 `realized(t−1→t)` 更新 —— 两者当帧均已知 |
| 门控机制（市场状态驱动） | ✅ | 波动率分位 / 涨跌家数比 / **截面离散度** |
| 门控温度 τ | ✅ | `softmax(logits/τ)`，τ 越小越集中 |
| 更新频率分层（日内/日频/事件） | 🟡 | 仅实现**日频**；日内频率需 L2 快照数据 |

**两处必须说明的实现决策**：

1. **λ₂（L1）用近端软阈值而非次梯度项。** Adam 会把梯度按二阶动量归一化，
   `λ₂·sign(w)` 的幅度被抹平 —— 实测把 λ₂ 放大 50 倍权重也几乎不变。改为
   `w ← sign(w)·max(0, |w| − ηλ₂)` 后 L1 才真正产生收缩与稀疏。
2. **门控用 numpy 手写反向传播**（而非 PyTorch），以保持回测路径完全确定性（I3）。
   监督信号是「近期因子 IC 向量」，即门控学的是「**在这种市场状态下哪些因子管用**」。

### §4 执行与验证层

| 设计要求 | 实现 | 说明 |
|---|---|---|
| 点前（PIT）架构 | 🟡 | framebt 的**因果令牌**提供等价保证：任何数据访问被强制过滤到 `issued_at` 之前，且令牌伪造被总线钳制。但设计文档的**双时间戳 + restatement 追加**针对财务数据，本数据集无财务数据 |
| 事件驱动回测引擎 | ✅ | **用 framebt 替代 NautilusTrader**：framebt 本身即确定性、单线程、固定 Δt 推进的事件驱动引擎，且回测/实盘共用同一回调接口 |
| 成交模型（滑点/佣金/冲击） | ✅ | 佣金(含最低)、印花税(仅卖出)、过户费、成交量滑点 |
| 实盘并行验证（信号差异率 < 5%） | ❌ | **无实盘**可并行 |

### §5 监控层

| 指标/机制 | 实现 | 阈值 |
|---|---|---|
| 截面 IC / ICIR(60日) | ✅ | — |
| FSC（因子排名自相关） | ✅ | < 0.5 预警 |
| 拥挤度 | 🟡 | **替代实现**：与「近期涨幅、换手率」的截面相关（无公募持仓数据） |
| CUSUM 变点检测 | ✅ | k=0.5σ, h=5σ，双侧，含去抖 |
| 卡尔曼滤波平滑 | ✅ | 一维，NaN 安全 |
| 三级预警 GREEN/YELLOW/RED | ✅ | 0.3 / 0.6 |
| 自动降权 1.0 / 0.5 / 0.0 | ✅ | |
| **参数敏感性安全阀** | ✅ | 网格不稳健则**只提示、不降权**（设计文档「重要警示」） |

### §6 自主因子发现

| 要求 | 实现 | 说明 |
|---|---|---|
| 符号回归（遗传规划） | ✅ | **自实现**（无 gplearn/deap/pysr）：树状 GP，23 个算子 + 时间窗终结符，锦标赛选择 + 精英保留 + 交叉/子树/提升/点变异 + 简约惩罚，适应度 = 截面 Spearman IC |
| 神经网络因子挖掘 | ✅ | PyTorch 编码器 + 因子头 + 预测头，损失 = `−IC + λ·正交惩罚`（可选依赖） |
| 正交化入栈 | ✅ | 逐截面回归取残差 |
| 增量信息检验 | ✅ | VIF（共线性）+ 增量 ICIR 的 t 统计量 |
| 影子运行 | ✅ | 记录候选信号 vs 实盘信号，要求天数 ≥ 20、相关 < 0.3、IC 持续为正 |
| 自动入栈流水线 | ✅ | 五级筛选，**每级拒绝理由完整记录**；初始权重 ≤ 5% |
| 季度重训练 | 🟡 | 机制齐备（`fit(epochs=...)`），但**本数据集无足够样本做真季度滚动** |

### §7 生命周期

| 要求 | 实现 |
|---|---|
| 字段：factor_id/expression/birth_date/source/weight/icir_60d/status | ✅ |
| 观察期（3 个月，权重 ≤5%）→ 提权 | ✅ |
| 退休（连续 60 日 ICIR<0.2 **且** CUSUM 报警） | ✅ |
| 康复（退休 120 日后 IC 恢复） | ✅ |

实现要求 **CUSUM 报警**与 ICIR 连续低迷**同时满足**才退休 —— 只看 ICIR 会把噪声误判为失效。

## 4. 验证方法论

`tools/validate_adaptive.py` 的流程刻意设计成**防止自我欺骗**：

1. **样本内选因子**：只用前 800 个交易日做筛选与去冗余；
2. **样本外回测**：其余 1251 日在 framebt 引擎上跑（在线学习从零开始）；
3. **因果审计**：抽样验证预计算面板 == 截断重算面板（逐位一致）；
4. **基准对比**：同样本外区间的等权买入持有；
5. **换手/成本透明**：报告累计成交额、年化单边换手、费用占初始资金比例。

### 实测结果

| 项 | 值 |
|---|---|
| 数据 | 24 只 A 股 × 2000 根前复权日线（2018-05 ~ 2026-10） |
| 因子库 | 57 个，样本内 10 个通过筛选，去冗余后 **8 个** |
| 因果审计 | ✓ 逐位一致（无前视） |
| **样本外总收益** | **+42.47%** |
| 基准（等权买入持有） | +16.71% |
| **超额** | **+25.76%** |
| 年化 / Sharpe / 最大回撤 | +7.15% / 0.37 / 31.53% |
| 成交 / 费用 | 856 笔，12.3% 初始资金 |
| 年化单边换手 | ~13.5×（偏高，见下） |

**必须强调的保留意见**：
- 年化单边换手 13.5× 很高，策略在扣除 12.3% 成本后仍跑赢，说明 alpha 足以覆盖成本；
  但**这样一个高换手策略对成本假设极其敏感**，实盘摩擦若高于建模会显著侵蚀超额。
- 验证池仅 24 只、且是**存活至今**的大盘股（存活偏差）；结论不可外推到全市场。
- 样本外仅一段 5 年历史，**不构成统计意义上的有效性证明**。

## 5. 开发中通过真实数据暴露并修复的缺陷

这些缺陷**只有跑真实数据才会暴露**，单元测试与合成数据都察觉不到：

| # | 缺陷 | 表现 | 根因 |
|---|---|---|---|
| 1 | `StandardRisk` 把**现金**当权益 | 满仓后所有订单被判「超最大订单比例」拒绝 | 误用 `Ledger.equity()`（其语义是现金） |
| 2 | `reserved_cash` 把**正在校验的订单自身**计入预留 | **整场回测零成交** | 预留集合含自身 → 可用资金被自己吃掉 |
| 3 | 引擎**从不调用 `rules.observe(frame)`** | **涨跌停在任何回测中从未生效** | 规则钩子没接线；此前测试只测规则对象、没走引擎 |
| 4 | 引擎未把 `settlement_cycle` 传给 `Ledger` | T+0 配置无效（账本恒 T+1） | 参数只传给了规则，没传给账本 |
| 5 | `decay_probability` 采信**历史**下侧变点 | **平稳序列 33%~53% 被误判 RED** → 虚假降权 | 中途一次下探后即便回升仍被反复采信 |
| 6 | `cap_weights` 先截断再归一 | 5% 观察期上限形同虚设（归一后回到 33%） | 归一化把压下去的部分又放回来 |
| 7 | L1 正则用次梯度项 | Adam 下惩罚**完全失效**（放大 50 倍无影响） | Adam 归一化抹平次梯度幅度 |
| 8 | `corrwith` 在零方差行返回 `inf` | `inf` 经 `.mean()` 传播成 NaN + RuntimeWarning | pandas 向量化实现的 0/0 落 inf 分支 |
| 9 | `safe_div(1.0, panel)` 构造 1×1 面板 | `wq094` **全为 NaN** | 标量未广播 |
| 10 | 滚动窗口 `min_periods > window` | `wq045` **全为 NaN** | 窗口 2 却要求 3 个观测 |
| 11 | 数据源未按 `adjust` 过滤 | 不同复权口径的 Bar 被混成一条序列（408 根却只有 400 个唯一时间戳） | 忽略了行内 `period`/`adjust` 列 |
| 12 | `vwap = amount/volume` 口径错配 | vwap 与 close 不同复权基准（755.8 vs 480.8） | `amount`/`vol` 是原始值，OHLC 是复权值 |

**第 5 项有可量化的经济影响**：修复后健康看板从「6 个 RED」变为「1 个 RED」，
策略样本外收益从 **+38.39% 提升到 +42.47%**（超额 +21.68% → +25.76%）——
误降权此前一直在无谓地砍掉有效因子的权重。

**第 12 项的修复方式**：额外回填 `adjust=0`（不复权）数据，解出复权因子
`f(t) = raw_close(t) / adj_close(t)`，据此给出与复权价同口径的
`vwap = (amount/volume)/f(t)` 与真实市值 `market_cap = raw_close × float_shares`。

## 6. 诚实的实现边界（按缺失原因分类）

### 6.1 数据缺失（无法通过写代码弥补）

| 设计文档要求 | 缺失的数据 |
|---|---|
| L2 行情、逐笔成交、委托量不平衡 | 只有日频 OHLCV（数仓有 `fakt_trade`/`fakt_intraday` 但仅 1 个交易日样本） |
| PIT 财务数据、restatement | 完全无财务数据 |
| 资讯事件、GMM 事件四分类 | 完全无新闻/事件数据 |
| 因子拥挤度（公募持仓重合度） | 无基金持仓数据 → 用「与近期涨幅/换手率的相关」替代 |
| 行业中性化 | 无行业分类数据 → 只做规模中性化 |
| 实盘并行验证 | 无实盘账户 |

### 6.2 依赖缺失（已用自实现替代）

| 设计文档技术栈 | 本环境 | 处置 |
|---|---|---|
| gplearn / deap / PySR | ✗ | **自实现**遗传规划（numpy + stdlib） |
| kats / ruptures | ✗ | **自实现** CUSUM + 一维卡尔曼 |
| statsmodels | ✗ | **自实现** Newey-West t 统计量、VIF、OLS 残差 |
| sklearn（GMM） | ✗ | 无事件数据，未实现 |
| NautilusTrader | ✗ | **用 framebt 替代**（同为确定性事件驱动，且是本项目已有能力） |
| DolphinDB | ✗ | **未实现**；其「流批一体」目标通过「同一份因子代码驱动研究与回测」达成同构效果 |

### 6.3 设计文档明确要求但本实现**未做**的

- **帧内事件队列 / 子步骤**：接口在 framebt 中已定义，多因子策略未使用。
- **处理预算模拟**（单帧 tick 处理裁剪）：未实现。
- **季度滚动重训练**：机制齐备但样本量不足以做真滚动。
- **期权 / 多时钟域**：设计与本策略无关，未涉及。
